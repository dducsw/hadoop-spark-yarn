# How I Use AI in This Project

## 1. Overview & Guiding Philosophy

The core mindset of this project is: **"AI-First, Tech-Driven, Human-in-Control"**.

- **AI-First**: I use AI from day one as a smart assistant to speed up research, explore solutions, and generate starter code.
- **Tech-Driven**: I embrace modern tools and engineering best practices to build a scalable and reliable Big Data platform (Hadoop, Spark, Hive, YARN, ClickHouse).
- **Human-in-Control**: I make every design decision, review and modify every line of code, and run all tests. AI never decides how the system works and never accesses real data.

---

## 2. Who Does What?

### My Role (Human Developer)
- **Make Decisions**: Choose the technologies, decide table schemas, and define business logic.
- **Write & Modify Code**: Write my own code or directly edit, customize, and improve the code and configuration files generated by AI to fit this project.
- **Review & Verify**: Carefully read and check all AI-generated code, SQL queries, and config files before adding them to the codebase.
- **Run & Test**: Execute Spark jobs on the cluster, check logs, and fix issues.
- **Own the Project**: Take full responsibility for the quality and security of the platform.

### AI's Role (Assistant)
- **Explain Concepts**: Help me understand complex topics like Spark execution, YARN resource allocation, and ClickHouse tables.
- **Generate Drafts & Templates**: Create starting code templates, configuration drafts, and utility functions based on my requirements.
- **Suggest Optimizations**: Recommend ways to write cleaner code, choose better data types, or speed up queries.
- **Help Debug**: Explain error logs and suggest possible solutions when jobs fail.

---

## 3. Data Privacy Rule: No Real Data

To keep data safe, I follow a strict rule: **AI never sees real data.**

- **Schemas Only**: I only share column names and data types (e.g., `SK_ID_CURR: INT`, `AMT_CREDIT: DECIMAL`) with AI.
- **No Private Info**: Real customer files, loan records, database passwords, and server IPs are never sent to AI.
- **Fake Data for Testing**: If I need AI to help write a test, I only provide small, fake sample rows.

---

## 4. How We Work Together

1. **Planning**: I define what table or job I need. AI helps suggest a clean schema or project structure.
2. **Coding**: AI helps write the template. I adjust the code to match my project standards.
3. **Debugging**: When I run into a Spark or YARN error, I share the error message with AI to understand what went wrong.
4. **Learning**: I ask AI to explain why a specific solution is better, which helps me improve my Data Engineering skills.

---

## 5. Summary

Using AI helps me build this Big Data project much faster while learning practical engineering skills. However, every decision, test, and line of code is reviewed, understood, and maintained by me.
